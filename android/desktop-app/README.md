## Source implemented

- Typing: a room-owned actor serializes four-second on notices and off on blank/send/edit/background/close. Native callbacks resolve names under that same owner; stale lookups cannot bring back a cleared indicator. No draft body enters typing requests. The Windows-local Online and typing switch disables visibility and emission immediately, fails closed on unreadable preferences or failed disable persistence, and updates the captured client's SDK presence for future sync requests. Enabling waits for preference persistence. The line uses shared one/two/many strings and static dots (motion/a11y announcement acceptance remains open).
- Initial DM receipt UI: native SDK receipts cover older messages, including receipts on hidden state events. Sent, delivered-from-a-hidden-read, and read icons follow the phone; only the newest own message has its text label. SDK pending/failed states win over read evidence. Account privacy is validated against the server before displaying read ticks and then follows SDK changes without allowing an unchanged stale cache to undo a more private server result. Groups have no DM ticks. Encrypted delivered acknowledgements, group reader avatars/sheet and automatic visible/foreground read marking remain separate work.

- Desktop navigation: Ctrl+K focuses and selects the current chat search (from settings/work it opens Chats); Escape dismisses menus, ends favourite reordering, clears focused search, or cancels reply/edit context while preserving ordinary text and in-flight edits. Enter/Shift+Enter retain the shared hardware-keyboard behavior.
- Within a workspace session, each account retains a separate reading position per room. Incoming messages follow only while at newest; history, reaction/edit updates and a new incoming message cannot pull someone away from an older message. A newly arriving own message follows the phone behavior. The labelled 48dp jump control resumes following. Automatic scrolling jumps without animation, respecting Reduce Motion.
- SDK daily separators survive the full vector index space and hidden items. Labels use the app language and local day, with Today/Yesterday and a year only for older years. Bubble radius/padding/footer follow own Android source. Every message keeps its clock time and full date/time accessibility label. Group sender names remain on every incoming row; only the current DM peer loses a redundant sender line, while former members and locked messages retain it.

- Native Compose window, Windows minimum size and high-contrast property, keyboard/focus controls and text selection. Compose 1.9.3/Material3 1.9.0 use the existing Kotlin 2.2.21 compiler and JDK17; Android versions are unchanged.
- `tools/desktop-resources.mjs` reads canonical Portuguese/English JSON and calls bipe-shared's own token solver for all six palettes/four contrast variants. It packages the existing icon, shared version/build and public Windows OAuth metadata. Typography uses the existing own Android `BipeType.kt` source. There are no hand-picked UI colour values.
- The pending-device phone-link controller is connected to QR, two-digit code, approval and key-transfer views. QR modules use integer scaling and a quiet zone. Account promotion remains behind successful protocol completion and protected persistence.
- Linked account restore and switching. Account appearance follows the SDK cache every five seconds, owned by the account. Palette/background changes first persist in the slot’s protected journal, then merge into a fresh authenticated server event, preserving privacy and unknown fields. Offline edits can retry and survive restart; a retired account cannot publish their completion. Device-local system/light/dark mode is separate from account settings.
- A joined SDK room stream and a dedicated favourite stream, shared vector reducer and shared favourite-order parser/sorter. Favourite tiles and ordinary list rows use one selected room identity and the same accent-filled selection surface. Each tab remembers its own selection/search. Unknown account types grant no work actions; company chats include groups and the second mode is Work.
- Favourites and history are disjoint sections of one scrolling list. The favourites use a three-column grid, larger photos, the synced stable order and unread dots/accessibility labels. History preserves SDK order. Scope, archive and search filters apply to both sections; a tag update moves a room without changing its identity.
- Favourite/unfavourite and reorder commands share right-click, long press, Shift+F10 and accessibility actions. Reorder mode supports dragging across grid lines and move-earlier/later actions. Tag/order intent is persisted under the account's DPAPI key before HTTP, merged with fresh server order/unknown fields, and retained for retry after a failed request or restart. A corrupt journal is preserved and disables writes.
- Avatar identity follows the account-type API: company rounded squares, personal/unknown circles, and circular group photos/member clusters. Exact registered official account IDs render the shared Bipe mark without downloading their mutable profile photo. Type requests coalesce within the owning account and retired results cannot update another account.
- SDK live timeline, back-pagination, encrypted-room text send through the SDK queue, sender/time/local-send state and composer. Failed local sends use their SDK send handles for a guarded retry, without withdrawing verification or ignoring device trust. SDK/virtual indices survive filtering into immutable UI snapshots. Unsupported message kinds and undecryptable messages remain visible as labelled rows.
- Received text is assessed by `chat.bipe.core.scamWarningKind` through the generated UniFFI bindings. Matching, normalization and priority stay in Bipe's Rust core; Windows adds no heuristic list or global event-id cache. Own/unreadable content is excluded. Library/ABI failures show a retryable failure instead of a successful no-warning result, and retries cannot replace an edited body or publish into a retired account.
- Warning cards read canonical title/body, Phosphor artwork and caution tokens. Money-pause kinds/duration come from the existing registry. The room-owned monotonic countdown runs once per message per room-open and disables text selection/copy during the pause, including the first frame. Matrix room and event links open in the workspace after account selection. Timeline link activation checks the assessed destination and money pause. Windows runtime tests cover all 11 detection and 82 warning vectors plus failure/cancellation/pause cases; live warning/copy-pause acceptance remains separate.
- `windows/oauth-client.json` is the single public Windows OAuth metadata source. Its registered server ID permits source QR testing; native callback/installer verification remains pending. SDK constants and packaged configuration are generated from it. Distribution tasks still require a verified dedicated record, reject the known Mac id and mismatched environment metadata, and never fall back to Mac/web or a client secret. See [`../../windows/README.md`](../../windows/README.md).
- Pending setup recovery ([#1473](https://github.com/bipe-chat/bipe/issues/1473)) rechecks the locked slot and refuses linked accounts. It restores a saved pending session only for SDK logout, journals the result, drains native ownership, then revokes the local key and clears files. A separate confirmed local-forget action explicitly leaves server removal unconfirmed. Cleanup journals/tombstones and retained native locks can be retried; other linked accounts are preserved.
- Composer drafts ([#1474](https://github.com/bipe-chat/bipe/issues/1474)) use the Rust SDK's room draft APIs inside this account's encrypted state store. One coalescing account queue restores text and reply targets, updates chat-list previews and drains accepted writes before client/key release. Blank replies preserve their target; cancelling a reply preserves the text. Failed loads stay noneditable; unsupported edit/attachment/rich-HTML drafts stay intact. Failed writes retain their text and owner for retry. A revision guard prevents a successful earlier send from erasing later typing or a changed reply target, including a change away and back. The text slice uses SDK Markdown construction.
- Message menus offer Reply and guarded Copy through right click, Shift+F10/Menu, long press and accessibility commands. Reply uses native SDK capabilities and `Timeline.sendReply`, with queue acknowledgement before clearing the matching draft. Quotes use SDK reply details, one-at-a-time detail loading and a bounded five-page search for the original, with a brief highlight. Deleted rows have no message menu; received edits show the shared Edited label. Unsent cancellation and moderation remain separate work.
- Sent own-message deletion has an explicit confirmation, account-bound target identity, duplicate-click admission and fresh native ownership/membership/power-level checks. The SDK sync owns the deleted-row update. Permission reads fail closed and refresh when opening the message menu; failures keep the message and show the shared error. Unsent cancellation, group moderation, optimistic/offline deletion presentation and the remaining message actions are not implemented by this slice.
- Own sent text edits use native `isEditable`, fresh membership/power checks and `Timeline.edit`. A sealed room-owned edit session overlays the normal composer, ends a reply, keeps its unsent text in the SDK store and restores it on cancel or successful queue acceptance. Blank/unchanged edits and repeat saves are blocked; immediate failures retain the edited text for retry. Leaving the room abandons only the transient edit, matching the phone model. Saved SDK Edit/attachment/rich-HTML drafts remain untouched/unsupported; edit-draft restoration and queued-edit failure UI remain further work. Photo, video and file captions use the SDK media-caption edit. Reply/edit bars use the phone's context icons/title/preview/close control, and Send/Save use the matching circular paper-plane/check controls.
- Room task groups own native objects/callback handles separately from their immutable account. Native objects are converted to snapshots and released; Compose does not hold Room/TimelineItem wrappers. Closing a room preserves its account, and failed native cleanup retains the account lock for retry. A pending or broken store shows a recovery failure; cancellation never silently deletes it or claims the partial server device was removed.
- Avatar thumbnails use the account's authenticated SDK media API and a bounded in-memory cache. Requests, cancellation and cached bytes belong to the account; changing account or photo resets the UI image state. DMs use the peer photo only. Groups use their room photo or up to three overlapping hero photos/initials. The chat header uses the same renderer. Unavailable or malformed images retain initials.
- Reaction counts and own selection come from SDK timeline snapshots. Only actual reaction pills appear under a message; there is no permanent Reactions label/button. Pills toggle the original full key; long press, right click and an accessibility action open the newest-first sender list. The message context menu follows the mobile layout: generated quick-reaction strip, More reactions, divider and applicable commands with shared Phosphor icons. More reactions opens the Windows emoji panel. Unsent, deleted and undecryptable messages cannot react. In-flight actions reject repeat clicks, retain native trust checks and show a retryable failure without inventing local counts.

- You/settings uses the canonical five root groups, order, titles and Phosphor icon tiles. Working pages cover local theme mode, all six palettes and four shared backgrounds (including the canonical fruit tile), read-only linked devices, legal/help links, licences, version and Windows notification/accessibility settings. Unsupported rows stay hidden. Privacy includes the account’s DM read receipt switch and the synced media preview choice in Chats.

Windows codec availability, cleanup after process interruption, and actual phone media interop require native acceptance. Voice recording has no Windows transcription or expiry registration in this slice. Sticker pack import, creation and animated playback are separate from sending and saving received stickers.
