# Bipe for Windows — native UI source

This standalone Compose Desktop x64 target is part of [bipe#1346](https://github.com/bipe-chat/bipe/issues/1346), stacked on the local secure-storage checkpoint #1345. Its window is called **Bipe**, with the existing Bipe icon and the shared `tools/version.mjs` version/build/commit. There is one sidebar and the account switcher is at the upper left.

**10 November 2026: uncompiled source checkpoint. MZ requested coding without builds. No Gradle/native build, push or CI dispatch has been run. There is no installer or tester artifact. Windows remains planned in the parity matrix. Mac feature work remains paused under ADR0288.**

## Source implemented

- Native Compose window, Windows minimum size and high-contrast property, keyboard/focus controls and text selection. Compose 1.9.3/Material3 1.9.0 use the existing Kotlin 2.2.21 compiler and JDK17; Android versions are unchanged.
- `tools/desktop-resources.mjs` reads canonical Portuguese/English JSON and calls bipe-shared's own token solver for all six palettes/four contrast variants. It packages the existing icon, shared version/build and public Windows OAuth metadata. Typography uses the existing own Android `BipeType.kt` source. There are no hand-picked UI colour values.
- The pending-device phone-link controller is connected to QR, two-digit code, approval and key-transfer views. QR modules use integer scaling and a quiet zone. Account promotion remains behind successful protocol completion and protected persistence.
- Linked account restore and switching; own account-data palette follows the SDK cache. Custom account-data observation is not exposed by this SDK, so the current source polls the local cache every five seconds, owned by the account. It does not poll HTTP or invent a second settings registry.
- A joined SDK room stream and a dedicated favourite stream, shared vector reducer and shared favourite-order parser/sorter. Favourite tiles and ordinary list rows use one selected room identity and the same accent-filled selection surface. Each tab remembers its own selection/search. Unknown account types grant no work actions; company chats include groups and the second mode is Work.
- SDK live timeline, back-pagination, encrypted-room text send through the SDK queue, sender/time/local-send state and composer. Failed local sends use their SDK send handles for a guarded retry, without withdrawing verification or ignoring device trust. SDK/virtual indices survive filtering into immutable UI snapshots. Unsupported message kinds and undecryptable messages remain visible as labelled rows.
- Received text is assessed by `chat.bipe.core.scamWarningKind` through the generated UniFFI bindings. Matching, normalization and priority stay in Bipe's Rust core; Windows adds no heuristic list or global event-id cache. Own/unreadable content is excluded. Library/ABI failures show a retryable failure instead of a successful no-warning result, and retries cannot replace an edited body or publish into a retired account.
- Warning cards read canonical title/body, Phosphor artwork and caution tokens. Money-pause kinds/duration come from the existing registry. The room-owned monotonic countdown runs once per message per room-open and disables text selection/copy during the pause, including the first frame. No link opener is implemented yet. Native tests are authored for all 11 detection and 82 warning vectors plus failure/cancellation/pause cases; they have not been compiled or run.
- `windows/oauth-client.json` is the single public Windows OAuth metadata source; its status is explicitly pending. SDK constants and packaged configuration are generated from it. Distribution tasks require a verified dedicated record, reject the known Mac id and mismatched environment metadata, and never fall back to Mac/web or a client secret. See [`../../windows/README.md`](../../windows/README.md).
- Pending setup recovery ([#1473](https://github.com/bipe-chat/bipe/issues/1473)) rechecks the locked slot and refuses linked accounts. It restores a saved pending session only for SDK logout, journals the result, drains native ownership, then revokes the local key and clears files. A separate confirmed local-forget action explicitly leaves server removal unconfirmed. Cleanup journals/tombstones and retained native locks can be retried; other linked accounts are preserved.
- Composer drafts ([#1474](https://github.com/bipe-chat/bipe/issues/1474)) use the Rust SDK's room draft APIs inside this account's encrypted state store. One coalescing account queue restores text, updates chat-list previews and drains accepted writes before client/key release. Failed loads stay noneditable; unsupported reply/edit/attachment drafts stay intact. Failed writes retain their text and owner for retry. A revision guard prevents a successful earlier send from erasing a later edit, including a change away and back to identical text. The text slice uses SDK Markdown construction.
- Room task groups own native objects/callback handles separately from their immutable account. Native objects are converted to snapshots and released; Compose does not hold Room/TimelineItem wrappers. Closing a room preserves its account, and failed native cleanup retains the account lock for retry. A pending or broken store shows a recovery failure; cancellation never silently deletes it or claims the partial server device was removed.

The source guard is written, but no server registration/deployment or native distribution validation has happened here. Pending metadata cannot start a link or pass the distribution gate.
- Released iOS and Android approval/key/history transfer; real Windows11 encrypted send/receive, same device after restart, offline phone use, reconnect, remote revocation and a second Windows profile. No dated device evidence exists yet.
- Validate the shared Rust warning path ([#1455](https://github.com/bipe-chat/bipe/issues/1455)) through actual Windows/JVM vectors, edits/room/account switching and native warning/copy-pause rendering. Source checks do not establish this acceptance. Do not claim the first-user acceptance in #1346 until warnings work on a real Windows client.
- Validate pending/duplicate-device recovery (#1473) through real Windows teardown, interruption/restart and released-phone device checks. A crash between successful server logout and journal persistence remains unresolved; local forgetting must not invent a server acknowledgement. Missing/corrupt credentials stay fail-closed.
- Account labels/photos and authenticated avatar/media loading, favourite context actions/reorder, requests/archive and complete group/work navigation. The initial avatar renderer is a name fallback/group initials collage, not a media-parity claim. Work and You currently show the account summary/phone-management instruction.
- Prove draft persistence/encryption (#1474) through the actual native SDK: same-slot restart, room/account/window changes, offline/queued/failed sends, failed writes, wrong-key refusal and no plaintext draft in DB/WAL files. Fifteen recovery/draft state tests are authored, not run. Remaining message actions/identity-change explanation and receipts, rich text/links, reactions, images/files/video, calls and the full suite matrix remain open. The composer is an initial text slice; attachment controls are not fake placeholders. Stored background choices/fruit artwork and palette editing still need their settings integration.
- Windows notices/transitive native licences, signed installer/update/version mapping and ARM. No installer/signing configuration has been invented; no user-facing changelog entry is claimed until actual client delivery.

Keep #1345/#1346 open, and Windows planned, until the real gates pass. Continue from the existing local branches rather than duplicate the SDK build. Preserve unrelated dirty sibling/factory work.
