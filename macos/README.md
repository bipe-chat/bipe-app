# Bipe for Mac: feasibility spike

Started 6 November 2026. Tracking: [bipe#1018](https://github.com/bipe-chat/bipe/issues/1018). Scope: [ADR 0266](https://github.com/bipe-chat/bipe/blob/main/docs/adr/0266-mac-first-full-personal-and-work-parity.md). Native desktop architecture: [ADR 0238](https://github.com/bipe-chat/bipe/blob/main/docs/adr/0238-native-mac-and-windows-apps.md).

`project.yml` creates a macOS 15+ SwiftUI app. CI builds Apple Silicon and Intel with the same Matrix SDK release as the phones. It reuses BipeKit's strings, rules and tokens, and the iOS client's SDK listener/vector adapters. It adds no dependency.

## First slice

- The Mac displays an MSC4108 QR code. The phone scans it in **Conectar um computador**. Enter the phone's check code on the Mac, then approve on the phone.
- Codes refresh after 25 seconds if nobody scanned them. A new attempt has its own store folder. Unapproved tokens are not persisted.
- After approval and key transfer, the Mac starts sync and displays joined rooms. The text timeline reads available history, sends messages and checks incoming text with the shared scam detector.
- The session, refresh token and random database key live in a separate, non-synced macOS Keychain service. SQLite stores are encrypted and excluded from backups. The app keeps no URL cache on disk and removes prepared photos at launch. A failed Keychain read never opens the store without its key.
- Restart restores the same device. A missing crypto store fails closed instead of making new keys under the saved device ID. SDK offline mode makes cached state available without waiting for a network response.
- An authentication refusal ends the local session. Delayed refresh callbacks cannot save it again after revocation. The encrypted cache remains local; this spike makes no remote-erasure claim.

The Mac holds multiple linked personal and company accounts. Each account keeps its own SDK client, sync and encrypted store. The first update copies the installed single-account Keychain record into an ordered account list without changing its device ID, tokens, store folder or encryption key. A failed migration preserves the old record. Refresh and revocation change only the affected account; linking an existing account twice cannot overwrite its working device.

Discarding a duplicate QR link returns a retained account slot to Retry. Installed stores still share the legacy database key; distinct per-account keys and lossless migration remain in bipe#1281, part of bipe#1226. The Swift SDK has no exported store-key rotation operation, so this retry fix leaves installed stores and keys intact.

A segmented control in the window toolbar holds Chats, Groups and You for personal accounts, or Chats, Work and You for company accounts. The account photo in the toolbar opens the switcher, as in the web toolbar; there is no account footer or extra navigation rail. Search is the native sidebar field, and the open chat's name sits in the toolbar. Each mode keeps its open chat. The You tab lists the five groups of the shared settings registry in the shared order, each with its tile, title, current state and chevron, and each opens its own screen. A group screen shows the registry rows the Mac can do. Your account shows the ways back, email, linked accounts and recovery key as read-only values, because changing them needs the phone (ADR 0266 rule 6). It also has a read-only list of linked devices and Sign out, which ends this account on this Mac and deletes its Keychain record and store. Notifications has the chat and group modes, whole-group mentions, invites, join pushes and news, and uses the Mac's system permission. Read receipts, palette, chat background and Mural follow the account through chat.bipe.settings, and the Mac reads them again when it comes to the front. Company Chats includes groups. RoomInfo.isDm is the DM rule, including groups with two members. Room-name search works in both lists. Unread status is shown with badges, without an Unread chip. Account rows show names and handles; Matrix IDs stay internal. Company account avatars are rounded squares. The Work overview reads live today counts, tool states, catalog items and people. It does not infer an owner role or expose phone-authorized operations. Work editors, videos/voice, global search, full notification lifecycle acceptance and calls remain in #1018. Windows follows the Mac evidence.

The app is named Bipe in Finder, the menu bar and About. It uses Bipe's generated icon, shared rounded typography, adaptive colors for light/dark/Increase Contrast, Phosphor glyphs and large native buttons. Desktop cards, message bubbles, account rows and the composer use the shared tokens. Rounded text follows the existing iOS/web type scale (body 17, subheadline 15, footnote 13), with accessibility scaling.

Favourites use the synced m.favourite tag and BipeFavouritesOrder account data, a three-column avatar grid, and the existing per-scope reorder rules. A separate favourite stream finds rooms outside the first loaded page; joined, favourite and archived streams share one SDK subscription union. Favourites do not appear again in the list. The account menu, list, favourites and timeline header load avatar thumbnails through the SDK. A DM uses its peer's photo, never the room avatar. A group uses its own photo or up to three other members as a cluster, with the same geometry as iOS and web. Unknown/company/official avatar rules follow the existing clients. Rows show names, available previews/dates, unread/mention indicators and mute state.

Sidebar rows and favourite cells use standard macOS selection with the current accent (bipe#1306). The list uses sidebar styling; the grid uses SwiftUI's selection shape style, with native button focus and context menus. Text follows selection prominence, and inactive focus/window states use the system selection treatment.

Reactions use the shared quick-emoji catalogue, the native character picker, SDK toggles, selected count pills and a sender list. Palette and background choices use the generated phone catalogue (six palettes, four backgrounds), with the same labels/order/defaults. The phone background renderer runs unchanged on Mac. The running Dock icon follows the palette; Finder keeps the signed bundle icon. Web uses the same generated catalogue and fruit artwork. These preferences remain local to each device.

The complete functionality assessment is generated in bipe/docs/product.md from bipe-shared/product/client-assessment.json, parity.json and desktop-plan.json. It separates implementation from real-device acceptance. Video messages, voice messages, audio calls, video calls, group calls and screen sharing each have their own row. Old web exclusions require review; an SDK method or successful compile is not evidence of device parity.

The conversation sidebar keeps a 300 to 440 pt width, with 360 pt preferred. Search attaches to the split view, and the account control belongs to the sidebar toolbar. A native sizing adapter repairs an already-restored narrow frame without clearing preferences, and keeps deliberate collapse available. Each account retains the search and selected chat separately for Chats and Groups. Quick reactions are native palette action buttons with explicit colour emoji images, avoiding empty text-only palette cells. CI checks restored geometry, native dragging/collapse and visible, distinct emoji artwork. The final app window still needs the visual acceptance in #1232.

The timeline shows the date separators, the chat start, call lines and group state lines in the two pill styles of spec timeline-rows, from the same `TimelinePill`, `CallLines` and `StateLines` as iOS. The SDK's unread marker, quote states and timestamp views come from the shared Apple `TimelineDetails`. Handle-change lines remain in #1165. Mac CI checks that both workflow filters cover every Swift file the Mac project compiles from the iOS app.

Replies show the original sender and a one-line preview, including loading, unavailable and deleted-original states. The SDK fetches missing quote details once; opening an original searches at most five history pages and briefly highlights the row. Edited messages keep their event time and show the shared Edited label. Redacted messages keep that time and a deleted placeholder, with no original content, quote, reactions or message actions. Quoted source text and link destinations participate in the local scam checks; a newly loaded quote can start the money pause. Unsent own messages are cancelled through the SDK send handle without a deletion dialog. Edit and delete failures have their own shared error messages.

The message and chat row menus come from bipe-shared registries/context-menus.json: order, titles and symbols. The Mac shows the commands that apply and that it has a handler for: reply, edit, copy, copy link, pin, forward, retry, delete and report on a message; send photos, favourite, reorder, read state, notifications and archive on a chat. Text replies use the SDK's reply relation. Composer text and reply targets live in the room's encrypted SDK store. Each account has an ordered draft-write queue, so reopening a room waits for edits from its dismissed view. Visible conversations send read receipts only while Bipe is active. The privacy switch keeps DM receipts private when off; group receipts keep the shared public-receipt rule.

Images use SDK-authenticated encrypted media retrieval, with account-scoped memory previews, a native viewer and Save original. The account's media preview policy is observed through m.media_preview_config; a failed initial fetch waits for a tap. A DM the person accepted from chat requests on any device waits for a tap, through the synced chat.bipe.request_rooms list; a room also waits until that list has been read. Photo sending includes captions, encrypted image descriptions, reply relations, metadata removal and standard/high quality. Animated GIFs keep frames and timing; Reduce Motion stops playback. Upload files remain available until the SDK attachment send finishes. Shared BipeMessageText renders formatted messages and clickable links without executing HTML or loading remote embeds. The scam detector checks hidden link destinations and image descriptions; money warnings pause links and copying, in the timeline and in the image viewer. Save original accepts only bytes that decode as a known image type, names the file by that type, and marks it with the system quarantine. Native regression tests use synthetic images and links. End-to-end image sending and real-account preview preferences still need device evidence.

Chat requests follow the chat-requests and chat-request specs: the Pedidos row, the box, and accept, decline, decline and block, and report. Accepting writes the room to `chat.bipe.request_rooms`, so its images wait for a tap on every device. Invites from an official account or an invite pair join by themselves. Photos stay hidden until the account's invite avatar setting allows them. The Mac has no address book, so contacts here are joined DMs, and the saved-name check of chat-request does not apply. The pencil in the sidebar starts a DM by @. The DM list shows one row per person through the same ADR 0141 rule as the phones.

Notifications follow the Mac rule in the notification-service spec. While the app runs and the Mac is awake, sync drives local notifications with the room's mode. An open chat in the key window has none. After quit or during sleep nothing shows, because the Mac has no push. After wake each room with new messages shows one notification. The Dock badge adds the tab counts of every account. A click opens the right account and chat. A preview build has an ad hoc signature, and macOS can refuse its notifications; the Dock badge does not depend on them.

QR codes use one binary byte segment, as the web does, so released phone scanners can read them. Apple's Core Image encoder mixed an alphanumeric MATRIX header with byte segments; the released iPhone scanner ignored that result. The native MIT-licensed Nayuki encoder is vendored unchanged, with source hashes and its notice in macos/QRCode. The regression test decodes the final bitmap with the released phone's byte-only rules. No phone update is needed for this compatibility fix.

## CI evidence

`.github/workflows/macos.yml` builds Debug and Release for both architectures. Hosted XCTest checks native SDK/SQLite loading without a server, Keychain error handling with synthetic records, same-device restoration, the approval gate and delayed refresh after revocation. Unit tests never read real credentials.

CI prefetches the pinned binary archives through the GitHub API into an explicit SwiftPM cache. The helper checks the package revision's manifest, archive version and SHA-256; SwiftPM keeps its own checksum and resolved-pin checks. This avoids failures of the GitHub release-page download path without changing the dependencies or package manifests. `tools/swiftpm-assets.json` holds the archives and their checksums.

The Release job uploads `bipe-mac-spike`, containing `Bipe-Mac.zip` and its SHA-256 checksum. After both Mac configurations and native tests pass on main, the publish job updates the public `mac-preview` prerelease. The downloads page reads that URL from bipe-shared/product/distribution.json. The ZIP contains Bipe.app for macOS 15+, on Apple silicon and Intel. It uses an ad hoc signature; Developer ID signing, notarization, store distribution and a supported updater remain later work. A build or synthetic test does not prove real-account linking or cross-device behavior.

MZ confirmed that phone linking works on 6 November 2026 with build 521 (ff3bede3). No phone update was needed. The remaining cross-device checks below still need evidence.

- Link from iOS and Android; reject a wrong check code or a declined request.
- Read available encrypted history and exchange text in both directions. Confirm local scam warnings.
- Put the phone offline after linking. Send and receive on the Mac.
- Quit and restart. Confirm the same device ID and history; repeat offline, then reconnect.
- Revoke the Mac on the phone. On reconnect it must leave the signed-in UI and must not restore the revoked session after restart.
- Repeat on Apple Silicon and Intel. Record failures and gaps without marking the full Mac product complete.
